AI 虚拟试衣大屏 · 一页产品方案

MUYE 沐野 · 商场门店场景｜大屏 3 步出效果，扫码到手机端完成决策与转化
产品原型 + 一页方案
真实模特 · 真实服装 · 摄像头实时试衣

一、目标用户与场景

主：到店但不愿排队试衣的顾客。怕麻烦、逛店时间碎片化；痛点是试衣间排队、脱穿成本高、看实物想象不出上身效果。

次：陪同者与等候者。顺手玩一下，带来停留时长与自然传播。

B 端：门店导购。大屏是留客工具，结果必须能被导购接手，否则线索断在屏幕上。

二、核心流程（≤3 步 / ≤60 秒）

① 驻足即开始② 选身形③ 选服装④ 生成⑤ 结果⑥ 扫码到手机

手机端是完整站点，不是一个试衣页：首页 → 分类 / 商品详情 → AI 虚拟试穿（站内入口） → 试穿结果 → 加入购物车 → 结算（门店自提 / 快递）→ 下单成功 → 我的订单 / 预约到店。扫码打开时直接落在"带着这件衣服的试穿结果页"，不需要用户重新找商品。

试穿页上的三个提效设计：① 360° 转圈看全身（左右滑动 / 点箭头，转满一圈自动切下一套）；② 自动搭配——选中一件就给出搭配件与合计，一键换穿；③ 按身高体重 + 门店现货推荐——算出身形与建议尺码，给 3 套并标注每套合计。男装形象自动切到男模特的试穿图，连衣裙等女装款自动隐藏。

全程零文字输入：不注册、不要手机号，每步只有"点卡片"一种动作，候选 ≤6 个，按钮点击区 ≥120px，先给时间预期再让人投入。

默认用虚拟形象（不采集人脸）；"真人试穿"是显式可选项，授权后才开摄像头。

三、大屏与手机端分工

大屏手机
角色公共场景的"看到"私人场景的"决策"
承担吸引、快速出效果、扫码桥接留存、尺码、库存、预约、支付
不承担不登录、不支付、不放长文详情不重复做大屏的生成交互
桥接一次性取件码 + 二维码（7 天有效，不填手机号也能用）

四、等待与失败（最容易答漏的一环）

  • 等待不空白：四阶段进度（读版型 → 贴合 → 渲染 → 出图）+ 剩余秒数 + 可取消。
  • 等待可离场：生成中就把二维码放出来，结果直接推到手机，人不必站在屏前。
  • 失败三级兜底：自动重试 1 次 → 云端失败回落本地 AR 截图 → 再不行给静态搭配图与商品信息。绝不空手而归。
  • 文案归因：责任放在系统侧（"不是你的操作问题"），并强调"搭配已帮你留着"。

五、隐私与合规

  • 默认不采集人脸：默认虚拟形象，不需要摄像头与手机号。
  • 真人试穿需单独授权：画面仅本机处理、不上传、不训练，生成后丢弃原始帧。
  • 自动清除：结果图 60 秒自动清除；无操作 90 秒清屏回首页（防身后的人看到）。
  • 一次性 token：取件码 7 天有效、可一键删除；不扫码就什么都不留。
  • 出海："不采集生物特征"这条设计同时规避 GDPR 第 9 条特殊类别数据与 CCPA/CPRA 敏感信息义务；EN 优先双语、区域尺码（US/EU/UK/亚洲码）与本地触达渠道（WhatsApp / LINE / IG）。

六、AI Native 的关键取舍

环节设计
双档渲染本地实时 AR（0 秒 / 免费 / 看版型颜色）＋ 云端换装模型（约 18 秒 / 按次计费 / 照片级成图），把等待与成本的选择权交给用户
模型接入接入层已做成可插拔：自建服务（ComfyUI / CatVTON / IDM-VTON，POST 人像＋服装＋体型参数）或 fal.ai 托管模型；未配置时自动回落本地预览。人像输入 = 按所选体型挑的数字模特，或顾客现场拍的那张照片——这就是"按体型生成"的落点
成本控制同款同体型成品图缓存、每店每日限额、失败不计费并自动降级
能力边界只做服装贴合，不做人脸识别；透明材质与复杂印花等不稳定品类只给静态搭配图；实时镜只在取景合格（上半身完整入镜）时才贴图，避免"假穿上"
可评测肩线/贴图偏移误差、P95 时延、失败与重试率、扫码率——换模型先跑回归

七、转化路径与指标

驻足 → 开始试穿 → 选形象/服装 → 生成 → 看到效果 → 扫码带走 → 手机端看尺码与库存 → 加购 / 预约试衣 / 联系导购 → 到店成交。

埋点：开始率、生成成功率与 P95 时延、扫码率、手机端停留与加购、预约试衣率、门店连带率、单次生成成本。线下最该盯的一个数：扫码率——它决定这块屏是玩具还是线索入口。
